## Executive Summary

MaxChat C++ is a mature, feature-rich IRC client port with unusually strong defensive coding for its stage: outbound IRC line injection is blocked, link previews have SSRF gates, script permissions default off, DCC has bounded writes and filename sanitization, and the test suite is broad (52/53 passing).

**One active test failure** blocks a clean CI signal: `main_window_link_preview` expects an empty application stylesheet after "Themes Off", but `applyTheme()` still injects a chrome-font CSS rule for the system theme.

**No critical remote-code-execution or memory-corruption bugs** were found in project `src/` during this audit. The highest-impact risks are:

1. **Plaintext credential storage** in `settings.json` (passwords, API keys, proxy creds).
2. **Lua `api.send_raw` / `api.say` / `api.mc_*` ungated** — any loaded script can emit arbitrary IRC regardless of `ScriptPermissions`.
3. **DCC chat session leaks** when re-offering to the same peer without teardown.
4. **SSRF redirect race** in async preview fetchers (DNS resolution vs. Qt redirect follow).
5. **IRC target parameter injection** — targets with embedded spaces are not validated before wire emission.
6. **Auto-executing `perform` lines** from imported/tampered network configs on connect.

The codebase's main structural debt is **`MainWindow.cpp` at ~9,850 lines** — a single god-object that concentrates IRC routing, scripting, previews, comic mode, DCC, themes, and MC DATA terminals. This increases regression risk and makes the test suite's one failure symptomatic of broader coupling.

## Verification Results

### Build & Tests

```
env QT_QPA_PLATFORM=offscreen ctest --test-dir build --output-on-failure -j2
```

| Result | Detail |
|--------|--------|
| **52 / 53 passed** | 98% pass rate |
| **1 failure** | `main_window_link_preview` |

**Failing assertion** (`tests/unit/main_window_link_preview_test.cpp:466`):

```cpp
themesOffAction->trigger();
QVERIFY(qApp->styleSheet().isEmpty());  // FAILS
```

**Root cause** (`src/ui/MainWindow.cpp:9265-9269`): when theme is `system`, `applyTheme()` resets the palette but still sets a non-empty chrome-font stylesheet:

```cpp
if (normalized == systemThemeId()) {
    qApp->setPalette(style->standardPalette());
    qApp->setStyleSheet(chromeFontCss);  // non-empty → test fails
}
```

**Resolution options:** (a) update the test to accept the chrome-font rule as intentional "Themes Off" behavior, or (b) move chrome font to a different mechanism (e.g. `QApplication::setFont`) so `styleSheet()` is truly empty.

### High (11)

#### H-1. Plaintext secrets in settings file

| | |
|---|---|
| **Files** | `src/core/SettingsStore.cpp`, `src/core/ConnectionPlan.cpp:99-111`, `src/core/DefaultNetworks.cpp` |
| **Issue** | SASL passwords, server passwords, proxy credentials, ImgBB/Imgur API keys stored as plaintext JSON in `~/.config/maxchat/settings.json` |
| **Impact** | Any process/user with read access to the config file obtains credentials; backups and shared configs leak secrets |
| **Fix** | OS keychain integration (Secret Service / Keychain / Credential Manager) or field-level encryption with machine-bound key |

#### H-2. Lua IRC APIs bypass permission model

| | |
|---|---|
| **Files** | `src/scripting/LuaEngine.cpp:845-858`, `src/scripting/ScriptPermissions.h`, `src/ui/MainWindow.cpp:2653+` |
| **Issue** | `api.send_raw`, `api.say`, `api.me`, `api.mc_send`, `api.mc_reply` are always registered with no permission gate. `l_send_raw` (line 227-229) forwards directly to `hostSendRaw`. |
| **Impact** | Any loaded script — even with all permissions off — can JOIN/PART/MODE/QUIT, flood, impersonate, or exfiltrate via NOTICE. Largest scripting trust-boundary gap. |
| **Fix** | Add `ScriptPermissions::ircWrite` (default off); gate destructive APIs; keep `echo`/`notify` safe |

#### H-3. DCC CHAT: orphaned sessions on re-offer

| | |
|---|---|
| **File** | `src/ui/DccManager.cpp:867-870` |
| **Issue** | `offerChat()` inserts a new `ChatRuntime` without calling `teardownChat()` on an existing session for the same peer. `acceptIncomingChat()` does tear down first (lines 1002-1005). |
| **Impact** | Leaked `QTcpServer`/`QTcpSocket`, duplicate signal handlers, possible cross-session data delivery |
| **Fix** | Mirror `acceptIncomingChat()` — `teardownChat(key)` before insert |

#### H-4. DCC SEND (active mode): no peer verification on inbound connection

| | |
|---|---|
| **File** | `src/ui/DccManager.cpp:324-334` |
| **Issue** | Passive-reply path verifies sender nick + token; passive-receive verifies peer IP when `host != 0`. Active **send** accepts the first TCP connection with no IP/token check. |
| **Impact** | LAN attacker or CTCP observer who reaches the listening port can intercept or block a file send |
| **Fix** | Mandate passive mode for sends, or verify connecting IP against advertised peer |

#### H-5. SSRF redirect race in preview fetchers

| | |
|---|---|
| **Files** | `src/services/ImageFetcher.cpp:81-92`, `src/services/OpenGraphFetcher.cpp:78-88`, `src/ui/MainWindow.cpp:2845-2853` |
| **Issue** | Redirect vetting uses async DNS (`resolvePreviewUrlPublicAsync`). Qt may follow a redirect to `127.0.0.1` or `169.254.169.254` before `abort()` runs. |
| **Impact** | Metadata SSRF to internal services via malicious redirect chain |
| **Fix** | Disable auto-redirect and handle manually after synchronous DNS check, or block until resolution completes |

#### H-6. `scriptHttpGet` blocks GUI thread

| | |
|---|---|
| **File** | `src/ui/MainWindow.cpp:2824-2869` |
| **Issue** | Nested `QEventLoop::exec()` on UI thread for gate + fetch (~10s timeout) |
| **Impact** | UI freeze, event re-entrancy, accidental DoS if script calls `api.http_get` in a loop |
| **Fix** | Async fetch with callback/coroutine; never block GUI thread for network |

#### H-7. OpenGraph fetch: no in-flight download size cap

| | |
|---|---|
| **File** | `src/services/OpenGraphFetcher.cpp:60-128` |
| **Issue** | `ImageFetcher` aborts on `downloadProgress` when `received > maxBytes`; `OpenGraphFetcher` only truncates at `finished` |
| **Impact** | Memory DoS via large HTML response linked in chat |
| **Fix** | Mirror `ImageFetcher`'s progress abort |

#### H-8. IRC target/nick parameter injection

| | |
|---|---|
| **Files** | `src/irc/IrcSession.cpp:266-268, 309-311`, `src/irc/CommandParser.cpp:232-258` |
| **Issue** | CR/LF stripping prevents newline injection, but targets like `nick extra` produce `PRIVMSG nick extra :msg` — multiple wire parameters from one crafted target |
| **Impact** | Unintended server-side command parsing from aliases, scripts, perform lines, or `/msg` |
| **Fix** | Validate targets: reject whitespace, leading `:`, control chars; RFC 2812 token rules |

#### H-9. Auto-executing `perform` lines (settings trust boundary)

| | |
|---|---|
| **Files** | `src/core/ConnectionPlan.cpp:106`, `src/ui/MainWindow.cpp:4142-4151` |
| **Issue** | On IRC registration, every `perform` line from network config runs automatically — slash commands via `sendCommandOrMessage`, others as raw IRC |
| **Impact** | Tampered/imported settings can run arbitrary IRC or client commands on next connect without confirmation |
| **Fix** | Prompt on first connect after import; or sandbox perform to a whitelist of safe commands |

#### H-10. Comic balloon layout uses stale character centers

| | |
|---|---|
| **File** | `src/comic/ComicRenderer.cpp:599-631` |
| **Issue** | Balloons laid out with `initialCx()`, then character positions recomputed via `placeCharsWidths()` — balloon `bx/by` not updated, only tail aim points |
| **Impact** | Visible misalignment between speaker and speech bubble when stack height forces reflow |
| **Fix** | Re-run balloon layout with final `cx`, or offset rows by delta |

#### H-11. Comic spill-check actor set differs from render set

| | |
|---|---|
| **Files** | `src/ui/MainWindow.cpp:8357-8446`, `src/comic/ComicRenderer.cpp:106-108` |
| **Issue** | `panelMinFont()` includes actors with no art (`nullptr` character); rendering skips them. Null actors still consume horizontal space. |
| **Impact** | Panel splitting decisions don't match what users see |
| **Fix** | Filter null-character actors from spill check |

## Module Summaries

### `src/irc/` (11 files)

**Strengths:** CR/LF injection blocked with tests; 512-byte wire limit with UTF-8-safe PRIVMSG splitting; SASL PLAIN chunked correctly; inbound flood caps (10 KB line, 4 MB backlog, 100 lines/tick); stale-socket guard; CTCP rate limit; MC DATA payload cap.

**Weaknesses:** Target validation gap; incomplete redaction; unbounded send queue; ignore-mask ReDoS; `sendRaw` return semantics (queued ≠ delivered).

### `src/core/` (18 files)

**Strengths:** `QSaveFile` atomic writes; mtime/size cache for settings reload; geometry key preservation; chat log path sanitization; `ChatBufferStore` scrollback caps; `FloodGuard` sliding window.

**Weaknesses:** Plaintext secrets; corrupt JSON silent failure; non-atomic read-modify-write; unbounded chat logs; `FloodGuard` map growth.

### `src/ui/` (80+ files)

**Strengths:** DCC bounded disk writes, filename sanitization, `.part` download pattern, 64-bit ack wrap, chat buffer caps; theme JSON validation; wallpaper path stripping; `UrlListDialog` scheme whitelist; `AnsiRenderer` HTML escaping.

**Weaknesses:** `MainWindow.cpp` monolith; GUI-thread network/DNS; theme test mismatch; DCC multi-network routing; unbounded script terminal output.

### `src/scripting/` (3 files)

**Strengths:** Per-script isolated `lua_State`; permissions default off; `os.exit` removed; native loaders/bytecode disabled; jailed `io.open`; timer floor 50ms; `runPrograms` gates `api.launch`; `network` gates `api.http_get`.

**Weaknesses:** IRC write APIs ungated; unbounded file reads; `getenv` with exec permission; erroring timers keep firing.

### `src/services/` (8 files)

**Strengths:** SSRF static rules + DNS public-only check; per-redirect re-vetting; image size cap during download; `og:url` scheme whitelist; remote images not auto-fetched by QTextBrowser.

**Weaknesses:** Redirect race; OpenGraph in-flight size; sync DNS in hot path; IPv6 rejection.

### `src/comic/` (8 files)

**Strengths:** Strong hostile-art defenses (`MaxDibDim` 4096, `MaxInflateBytes` 32 MiB) with unit tests; thoughtful heuristics (outlier face drop, body cleaning); polished renderer (tails, cloud/burst balloons).

**Weaknesses:** Balloon/character layout bug; spill-check mismatch; unbounded cache; pre-guard `readAll()`.

### `src/spell/` (6 files)

**Strengths:** Clean `Speller` abstraction; factory stub pattern; Hunspell edge-punctuation normalization; multi-path dictionary catalog.

**Weaknesses:** Backend semantic mismatch on unloaded `isCorrect()`.

### `src/upload/` (5 files)

**Strengths:** Consistent structure; shared `QNetworkAccessManager`; `QHttpMultiPart` parented to reply; Imgur CR/LF header sanitization.

**Weaknesses:** No timeouts; no in-flight guard; ImgBB key in query string; large image memory spikes.

## Positive Patterns (Security & Quality)

1. **Defense in depth on outbound IRC** — newline strip, wire-length split, flood throttle, plaintext-auth gate.
2. **Inbound DoS resistance** — line size cap, backlog cap, drain throttling, idle watchdog with PING probe.
3. **DCC hardening** — passive token binding, accept policy, anti-flood caps, Windows reserved-name strip, resume validation.
4. **Lua sandbox defaults** — all capabilities opt-in; dangerous `os`/`io`/`package` stripped or jailed.
5. **Link preview SSRF** — blocklist + DNS resolution check + per-redirect re-vet (race aside).
6. **Path safety** — chat logs, CTCP SOUND, theme delete, script file jail all sanitize paths.
7. **Test coverage** — 53 targets spanning IRC session, command parser, DCC, Lua, themes, comic art, link previews, network import.
8. **IRCv3 message tags** — proper unescaping; trailing whitespace preserved.
9. **Settings atomic write** — `QSaveFile` with geometry preservation across partial saves.
10. **MC DATA** — payload size cap; token validation in codec.

## Conclusion

The MaxChat C++ `src/` tree is production-leaning for an IRC client at v0.1: security-conscious defaults, broad tests, and deliberate hardening in IRC wire handling, DCC, and scripting. The gap between "safe by default" scripting and ungated IRC write APIs is the most surprising inconsistency. Structural concentration in `MainWindow.cpp` is the main maintainability risk going forward.

No changes were made to the codebase during this audit. This report is independent of prior `AUDIT-CODEX-*` and `AUDIT-MIMO-*` documents on the same date.
